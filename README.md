# Dimension Finance

**Financial Management Platform** — a frontend-only financial management and accounting platform built with Next.js, TypeScript, Tailwind CSS and shadcn/ui.

> **Build disclaimer:** This is a frontend-only Financial Management and Accounting platform. It uses fictional mock data and does not connect to a production database, authentication provider, bank, payment provider, tax authority, accounting platform or external business API.

## Overview

Dimension Finance is a complete, production-quality frontend for a modern enterprise finance application: an executive dashboard, a full general ledger and chart of accounts, receivables and payables workflows, expense management, banking and reconciliation screens, budgeting and forecasting, fixed asset tracking, a financial report center, analytics, and administration settings — all built as real, navigable Next.js routes with realistic (but entirely fictional) data.

There is no backend. Every number on screen is generated by deterministic local data generators in `src/data/`, so the app is fast, fully static-data-driven, and safe to explore or extend without any risk of real financial side effects. It is built to a standard other developers can read, learn from, and use as the foundation for their own project.

## Features

- **Executive dashboard** — KPI cards, 8 charts (revenue vs expenses, net profit trend, cash flow, revenue/expense breakdowns, budget vs actual, AR/AP aging) and 10 live-data widgets
- **Global command menu** (`⌘K` / `Ctrl+K`) — search across accounts, customers, suppliers, invoices, bills, transactions, payments, expenses, assets and reports, or jump to any screen
- **Company and fiscal period selectors** — switch between three fictional Argent Group entities and any year/quarter/month
- **Enterprise data tables** — search, column filters, sorting, pagination and column visibility, built on TanStack Table
- **Print-friendly documents** — invoices, bills, and financial statements render a clean, letter-sized printable view
- **Config-driven forms** — a single reusable form generator (text, textarea, select, combobox, date picker, checkbox, radio, switch) powers every "New Record" dialog across the app
- **Fully responsive** — from 320px mobile up through wide desktop layouts, with a drawer sidebar and compact header on small screens
- **Light / dark / system themes** with multiple color presets
- **Demo Mode** — clearly labeled throughout; every mutating action (approve, reconcile, save) shows a toast and never persists data

## Technology Stack

- **Framework:** Next.js 16 (App Router), React 19, TypeScript
- **Styling:** Tailwind CSS v4, shadcn/ui (radix-nova style)
- **Tables:** TanStack Table v9
- **Charts:** Recharts
- **Forms:** React Hook Form + Zod
- **State:** Zustand (layout/theme preferences), React Context (company/fiscal period workspace)
- **Tooling:** Biome (lint + format), Husky + lint-staged

## Architecture

The project follows a colocation-based structure: each route owns its screen-specific components under a local `_components/` folder, while shared building blocks live centrally.

```
src/
  app/(main)/                # Every Dimension Finance route, one folder per screen
    dashboard/
    accounting/ accounts/ general-ledger/ journal-entries/ trial-balance/ period-close/
    receivables/ customers/ invoices/ payments/ credit-notes/ ar-aging/
    payables/ suppliers/ bills/ debit-notes/ ap-aging/
    expenses/ expense-categories/ expense-approvals/ reimbursements/
    banking/ bank-accounts/ bank-transactions/ reconciliation/
    budgets/ forecasts/ variance-analysis/ cost-centers/
    assets/ depreciation/
    reports/ ...
    analytics/ ...
    settings/ ...
    _components/              # Shared shell: sidebar, header, command menu, selectors
  app/(external)/platform/    # Module overview / landing page
  components/
    finance/                  # Reusable finance UI kit (KPI cards, data table, charts,
                               #   status badges, print portal, entity form generator, ...)
    ui/                       # shadcn/ui primitives (do not modify directly)
  data/                       # Local mock data — the "backend" of this app
  lib/finance/                # Money/date formatting, aging-bucket calculations
  lib/mock/                   # Seeded random generators used to build mock data
  types/finance.ts            # Shared TypeScript types for every financial entity
```

## Mock Data Approach

All data lives in `src/data/` and is generated once, at module load, by seeded pseudo-random generators in `src/lib/mock/random.ts` — the same seed always produces the same numbers, so the app renders identically on the server and the client with no hydration mismatches, and no database is ever involved.

The dataset includes 80+ chart-of-accounts entries, 200+ general ledger transactions, 80+ journal entries, 50+ customers, 100+ invoices, 80+ receivable payments, 40+ suppliers, 80+ bills, 100+ expenses, 120+ bank transactions, 30+ budgets, 60+ fixed assets and 15+ notifications, alongside credit notes, debit notes, reimbursements, forecasts, cost centers, and fully derived financial reports (trial balance, P&L, balance sheet, cash flow, tax summary) that reconcile against the underlying ledger.

Every company, customer, supplier, employee and transaction name is fictional.

## Responsive Design

Every screen is designed and tested from 320px mobile through 1440px+ desktop:

- The sidebar becomes a drawer, and the header collapses to a compact bar
- Data tables scroll horizontally inside their own container rather than the page
- Filters move into a Sheet on small screens
- Charts and KPI grids reflow into single/two-column layouts
- Forms go single-column on mobile

## Local Development

This project uses npm.

```bash
npm install
npm run dev
```

The app runs at [http://localhost:3000](http://localhost:3000) and redirects to `/dashboard`.

Other available commands:

```bash
npm run build     # Production build
npm run lint       # Biome lint
npm run format     # Biome format
npm run check      # Biome check (lint + format)
npm run check:fix  # Biome check, auto-fixing what it can
```

## Using This as a Starting Point

The codebase is organized so it's straightforward to build on:

- Add a new screen by creating `src/app/(main)/<screen>/page.tsx` plus a local `_components/` folder, and register it in `src/navigation/sidebar/sidebar-items.ts`.
- Add a new entity by defining its type in `src/types/finance.ts`, a generator in `src/data/`, and reusing the existing data table, chart, and form primitives in `src/components/finance/`.
- Swap the mock data layer for real API calls without touching the UI layer — every screen already reads from a single typed data module per entity.
